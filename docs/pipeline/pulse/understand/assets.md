# Pulse — images, icons and performance (reader note)

Area: how the 49 Pulse images become shipped app assets, how they are referenced, how they render,
and what they cost. Written 2026-10-11, read-only pass on branch `pulse-redesign`. Nothing in the
codebase was changed. Every number below was measured on this machine; the probe scripts are listed
in §13.

Owner decisions `00-owner-decisions.md` D1-D4 are taken as final (Pulse is the only look, one accent,
"keep the mechanism cheap to bring back"; the muscle selector moves onto the "Edzés" tab; frontend
only; local commits, the repo is public).

### 1.3 The rules already in force

- **Images always reserve their box** — `DESIGN.md:505` (rule 30; "20 unreserved images on one list
  was F-13"), implemented globally at `src/index.css:76`:
  `img, video { display: block; max-width: 100%; height: auto; }`. Two consequences for Pulse:
  an `<img>` reserves its box only if it carries `width` and `height` attributes (or an
  `aspect-ratio`); and `max-width: 100%` will silently shrink a hero that is meant to bleed past
  its container — the component has to opt out for those.
- **Never `#000`** — `DESIGN.md:497` (rule 22, "pure black smears on OLED"). Every black-background
  Pulse source has true `#000` edges (§2.2). Whatever technique is chosen must never paint them.
- **check-tokens** (`scripts/check-tokens.mjs:16-17,24-34`) scans every `.ts/.tsx/.css` under `src`
  except `tokens.css` for raw hex and `rgb()` literals. A generated manifest under `src` must carry
  no colour; `.json`, `.svg` and image files are not scanned. Its colour-utility rule
  (`:343-357`) reads any `text-…`, `bg-…`, `fill-…`, `stroke-…`, `ring-…`, `border-…`,
  `outline-…`, `divide-…`, `decoration-…` token as a class, so **a slot name must not start with
  one of those words**.
- **Gates import source into bare Node**: `scripts/check-nav-active.mjs:27` imports
  `src/app/navTabs.ts` with Node 24's type stripping. `navTabs.ts` therefore cannot import a
  module that imports an image (`ERR_UNKNOWN_FILE_EXTENSION` before the first assertion). The tab
  icon in `navTabs.ts` has to be a string key.

### 1.4 CSP, service worker, Capacitor

- CSP (`backend/server.js:95-117`): `img-src 'self' data: blob:` (`:102`), `media-src 'self' blob:`
  (`:103`), `font-src 'self'` (`:104`), `style-src 'self'` with no `'unsafe-inline'` (`:101`),
  `worker-src 'self'`, `manifest-src 'self'`. Bundled same-origin images, `data:` URIs (what Vite's
  asset inlining produces) and `blob:` URLs (a canvas-tinted icon) are all allowed; a CDN image or a
  third-party font origin is not. React writes styles through the CSSOM, so `style={{…}}` is not
  blocked; a literal `<style>` tag would be. A same-document SVG `filter="url(#id)"` is fine.
- The backend serves no static files (no `express.static` in `backend/`), so who serves
  `frontend/dist` and with which `Cache-Control` is not defined in the repo (owner question 6).
- Service worker (`public/sw.js`): precaches only `SHELL = ['/', '/manifest.webmanifest',
  '/favicon.svg', '/icon-192.png']` (`:32`); never touches `/api/` or `/healthz` (`:70`); for every
  other same-origin GET it is **cache-first, for ever** (`:103-104`) and stores any `ok` + `basic`
  response on first use (`:110-112`). A cache is retired only by changing `VERSION`
  (`'tracker-shell-v1'`, `:28`). It registers only in production web builds, not in dev and not in
  the Capacitor shell (`src/lib/registerSW.ts:44-49`).
- Capacitor: only `@capacitor/core` and `@capacitor/haptics` are dependencies; there is no
  `capacitor.config.*` and no `android/` or `ios/` project. In a future native build every asset is
  inside the app package, so the on-disk total (§3) is what the app grows by.
- PWA identity is still the old look: `index.html:9` theme-color `#0B0D10`,
  `public/manifest.webmanifest:11-12` `theme_color` / `background_color` `#0B0D10`,
  `backend/scripts/build-icons.mjs:35` `BACKGROUND = 0x0b0d10`, and `favicon.svg` is a purple mark
  (`#7e14ff` × 20, `#863bff`, `#47bfff`). Pulse's canvas is `#0B0D0A` and its only colour is lime.
  No Pulse app icon exists among the 49 images (owner question 3).

## 3. Formats, sizes, weight

### 3.1 Target sizes per slot

Rule: the largest size a slot is drawn at, times the density, capped at the source size (never
upscale). `srcset` uses **width descriptors** plus a `sizes` value computed from the rendered width,

figure at 105 / 189 / 195 pt, the coin at 20 / 22 / 188 pt).

Density policy, with the reasons:

- **One file for anything drawn at 56 pt or less** (icons, equipment, medal). At 96-168 px these are
  2-7 kB each; three densities would triple the file count to save under 20 kB in total. The browser
  downscales.
- **Figures get 1x / 2x / 3x.** The panel grooves are 1-2 px lines; at 3x the file is the source
  resolution (585 of 597 px). This is the one family where 3x is visible.
- **Photographs stop at 2x.** They are soft, low-key and feathered; two of the seven cannot reach 2x
  at their largest placement anyway (`hero-plates` 1.9x, `hero-kettlebell` 1.7x). A 3x phone takes
  the 2x file. Not shipping 3x heroes keeps 363 kB off the disk.

### 3.4 The budget

## 4. Where the files live and how code reaches them

### 4.1 `src/assets/pulse/`, not `public/`

`public/sw.js:103-104` answers any cached same-origin GET from the cache without asking the network,
and `:110-112` caches whatever it fetched. A file in `public/` keeps its URL when its bytes change,
so a returning user would see the old tab icon until somebody remembers to bump `VERSION`. Files
imported from `src` get a content hash in their name, which is exactly the assumption the worker's
comment states ("hashed build output is immutable", `sw.js:101-102`). It also gives a build error —
not a broken image — when a file is missing.

```
frontend/
  assets-src/pulse/assets.json      pipeline input: slot table (NOT under src → not bundled, not linted)
  scripts/build-pulse-assets.mjs    the asset script (§8)
  scripts/check-assets.mjs          the gate (§4.4)
  src/assets/pulse/
    img/<slot>-<width>.webp         GENERATED, committed (49 files, 0.84 MB)
    slots.ts                        GENERATED, pure TypeScript — importable by bare Node
    urls.ts                         GENERATED, Vite-only — the one file that imports images
    index.ts                        hand-written: the public API of the folder
  src/ui/media/Pic.tsx              the one component that renders a bundled raster
  src/ui/media/UserPhoto.tsx        the one component that renders user media (§7.4)
```

The 11 MB of master PNGs stay outside the repository (it is public — D4 — and the images are
AI-generated with unchecked terms, `0000 Index.md` "Honest limits"). The script takes the master
folder as an argument; the outputs are committed, the same arrangement `backend/scripts/build-icons.mjs`
uses ("the PNGs are committed", `:24`). Owner question 2.

### 4.5 One Vite setting that otherwise decides this silently

`build.assetsInlineLimit` defaults to 4096 bytes: every imported asset smaller than that is turned

## 5. "An image glowing out of black with no frame"

### 5.1 The three ways to do it

| | Technique | File |
|---|---|---|
| A | `mix-blend-mode: lighten` on the image — what Figma does (`pic()`, `app-kit.src.js:104`: `r.blendMode = 'LIGHTEN'`) | opaque, true-black edges, as delivered |
| B | pre-composite onto the canvas colour, `out = max(pixel, canvas)`; optionally a CSS mask on the edge (`shell-gates.md` §5.2 "Option B") | opaque rectangle in the canvas colour |
| C | **bake the alpha into the file** — "knee alpha" | RGBA, transparent where the source is black |

The knee alpha, per pixel, with `canvas = (11, 13, 10)` and `K = 32`:

```
lit   = max(pixel, canvas)                      per channel — what lighten would show on the canvas
alpha = clamp( max over channels of (pixel − canvas) / K , 0, 1 )
rgb   = canvas + (lit − canvas) / alpha         (canvas where alpha = 0)
```

Composited over the canvas this gives `alpha·rgb + (1 − alpha)·canvas = lit` — the approved lighten
picture, exactly, before compression. `rgb` never exceeds `canvas + K`, so a faint pixel cannot
carry a bright colour that a lossy codec could smear into a fringe. A pixel at or below the canvas
is fully transparent, so the source's `#000` is never painted (`DESIGN.md:497`).

### 5.2 What breaks with A — measured in a browser

Probe: a black square with a soft off-white disc and `mix-blend-mode: lighten`, on a coloured
canvas, inside twelve kinds of parent (`blend-test.html`, §13), rendered by the session's Chromium
pane over `http://127.0.0.1`.

| # | The image's parent has… | Result |
|---|---|---|
| 1 | nothing special | blends — no rectangle |
| 2 | `transform: translateY(0)` | **black rectangle** |
| 3 | `opacity: .99` | **black rectangle** |
| 4 | `will-change: transform` | **black rectangle** |
| 5 | `isolation: isolate` | **black rectangle** |
| 6 | `position: sticky` | **black rectangle** |
| 7 | `filter: brightness(1)` | **black rectangle** |
| 8 | `transform` and its own canvas-coloured background | blends |
| 9 | `container-type: inline-size` | blends |
| 10 | a different (sheet-coloured) background | blends against the sheet |
| 11 | sheet background and `transform` | blends against the sheet |
| 12 | `position: relative; z-index: 0` | **black rectangle** |

Seven of twelve fail, silently. An element blends only with what its own stacking context has
painted; any ancestor that forms one without an opaque background of its own leaves the image
blending against nothing.

What that means here:

- **Page transition.** Pulse's own motion spec — "content rises 8 px with a `base` fade"
  (`Pulse System.md` §2.4) — puts `transform` and `opacity` on a wrapper around the hero: rows 2
  and 3, for 250 ms on every navigation. The box is `#000` on a `#0B0D0A` canvas (11-13 levels
  apart, visible on OLED), then pops away when the animation ends. `AnimatePresence` panels already
  exist (`ui/feedback/variants/E10Tabs.tsx:349-506`, `E14E20.tsx:298-476`).
- **Permanent cases.** A sticky header (row 6) and any positioned layer with a `z-index` (row 12 —
  e.g. the content layer under the bottom fade) fail for good, not for 250 ms.
- **Non-black surface.** On the bottom sheet (row 10) lighten does blend, but against `s2`
  (`#1E2219`): every tone darker than 30 / 34 / 25 is clipped to the sheet, so the image flattens.
- **Cost.** A blended element forces its stacking context into an off-screen surface; twenty
  blended thumbs in a scrolling list is an avoidable risk on a low-end WebView.

### 5.3 B and C, measured

73 encodes (figures, heroes, covers, portrait, equipment, every density), compared with the
reference picture `max(pixel, canvas)`:

| Variant | Size against the opaque file | Mean difference from the reference (levels of 255) | Border ring: mean distance from the canvas |
|---|---|---|---|
| B — pre-composited, WebP q 80 | 0.94× | 1.25 | 0.389 |
| B — pre-composited, AVIF q 55 | 0.94× | 1.66 | 0.717 |
| **C — knee alpha, WebP q 80 / alpha 100** | **2.0×** (heroes 2x: 371,872 vs 185,878 B) | **0.75** | **0.008** |
| C — knee alpha, AVIF q 55 | 2.4× of opaque AVIF (292,691 vs 121,601 B) | 0.92 | 0.007 |

| luminance as alpha, AVIF | 1.8× of opaque AVIF (224,329 B) | same change | — |

- C's edge lands on the canvas to within 0.008 of a level: the rectangle does not exist. B's flat
  border is 0.4-0.7 of a level off after compression, which is why B needs a CSS mask as a second
  mechanism.
- C costs bytes: +375 kB across the whole set (839 vs 465 kB), at most +54 kB on one screen
  (`hero-kettlebell` 41 → 95 kB).
- The knee width was tuned (`knee.py`): `K = 16` is 20 % smaller (`hero-chalk` 65.7 → 51.7 kB) but
  makes pixels only 16 levels above the canvas opaque, which are darker than the sheet — a dark rim
  on `s2`. `K = 32` keeps every opaque pixel above ~43, lighter than `s2` (max 34). `K = 48` adds
  18 % for nothing. Blurring the alpha makes WebP 57 % larger (its alpha plane is lossless);
  `alphaQuality 60` saves 9 %. Keep `K = 32`, `alphaQuality 100`.

A visual check (`sheet-grip-amplified.png`): lighten on the canvas and the decoded knee-alpha WebP
on the canvas are indistinguishable at 6× amplified contrast; the same holds on `s2`; the raw file
on the canvas shows the box.

### 5.4 Why not B, and what this replaces

B is sturdier than A but keeps three liabilities that C does not have:

1. **It is still a rectangle.** It paints the canvas colour over whatever lies under its dark part.
   An absolutely positioned hero paints above in-flow text. On Home the image box is 216 × 180,
   right-anchored (`home-1.body.js:19-20`) and starts 9 pt to the right of the numerals at 402 pt;
   Pulse supports 360-430 pt with the numeral scaling as `min(124px, 31vw)` (`Pulse System.md` §3),
   so the two boxes meet on a narrow phone. With alpha an overlap of the black part is harmless.
   With B it erases ink unless z-order is managed — and managing z-order is how row 12 happens.
2. **It is wrong on the sheet**: a canvas-coloured box on `s2`. No approved frame puts an image on
   a sheet today (the five frames that call `bottomSheet` contain no `pic`), but a picker with
   equipment thumbs is the next obvious one.
3. **It needs a gate that walks ancestors** for a non-canvas background, plus the CSS mask.

So, against the sibling notes: no `mix-blend-lighten` utility (listed as allowed in
`tokens-type.md:244,480` — drop it), no `GlowImage` ancestor gate (`primitives.md` row 15), no
re-pointed `check-aurora` (`shell-gates.md` §5.2). `check-aurora` retires with `AuroraBackdrop`; its
heir is one line of `check:assets` (assertion 6: no `mix-blend-` in `src`).

What C still bakes in is the canvas colour, in the script constant. On a different dark canvas the
feather still dissolves correctly (that is what alpha is for); only the deepest tones of the opaque
interior would sit at the old canvas value. D1 fixes the canvas, and assertion 7 pins the copy.

### 5.5 What remains in CSS — the `Pic` component

- `<img>` with `width` / `height` from the manifest, `srcSet` + `sizes`, `alt=""`, `decoding="async"`,
  `draggable={false}`. Props: `slot`, `width` (pt), optional `lit`, `priority`, `bleed`, `alt`.
- `bleed` sets `max-width: none` — `src/index.css:76` would otherwise shrink a hero to its container.
  The screen scaffold needs `overflow-x: clip` (not `hidden`: `clip` makes no scroll container and
  does not break `position: sticky`), or a hero running 17 pt past the right edge makes the page
  scroll sideways.
- "Lights-on": opacity 0 → 1 over `--duration-slow` once the image has decoded (`onLoad`, or
  `img.complete` for a cached one), on the `<img>` itself. Reduced motion: no fade. Until then the
  reserved box is empty — Pulse draws no skeleton for an image ("images are withheld",
  `Pulse System.md` §4).
- Nothing else: no blend, no mask, no wrapper, no background.

## 6. The lime-lit active icon

### 6.1 What the lit icon actually is

It is not a second render. `icons_v2.py:15-43` (in the temp folder, §2.5) makes both states from one
master: idle = `levels(master, gamma 0.62, lo 18, hi 215)`; lit =
`tint(levels(master, gamma 0.70, lo 18, hi 225), LIME)`, where `tint` maps luminance `t` to

```
t < 0.6 :  accent × (0.22 + 0.78 · (t / 0.6)^0.85)          shadows → deep olive, mids → the accent
t ≥ 0.6 :  accent + (255 − accent) · 0.75 · (t − 0.6) / 0.4  highlights → almost white
```

Measured (`icons.py`): recomputing this from `tab-*.png` reproduces the five approved
`tab2-*-active.png` with **mean error 0.00, max 0**. The coach, admin and medal variants come from
the same function (`app/grade_app.py:118-125`). From the shipped idle raster alone, a one-dimensional
lookup on luminance reproduces the approved lit icon with mean error 0.05, 99th percentile 1,
max 7 levels (all seven icons).

### 6.2 The options

| Option | Error against the approved lit icon (mean, of 255) | Cost | A different accent needs |
|---|---|---|---|
| **Second raster, made by the asset script** | 0 | 7 files, ~21 kB (all 14 icons: 43 kB) | rerun the script with the accent: 7 files, ~21 kB per accent |
| CSS mask + flat fill (`mask-image: url(idle)`, `background: var(--accent)`) | 14.7 (worst icon 19.4) — and no shading: the door of the house, the three spheres in the bowl, the edges of the bars all vanish into a silhouette | 0 files | nothing |
| Mask + a blend of the grey icon over the accent | multiply 57.6 · overlay 14.6 · hard-light 24.5 · luminosity 41.9 — wrong tones, and a blend mode inside a `fixed` bar (§5.2) | 0 files | nothing |
| Runtime lookup: SVG `feColorMatrix` + `feComponentTransfer` (`filter: url(#lit)`), or a canvas → `blob:` URL | ≤ 0.07 mean, max 7 | 0 files, ~40 lines, one more runtime mechanism; SVG filters on HTML content render differently per engine — not tested here | nothing, any colour, including a user-picked one |

### 6.3 Recommendation

Second raster now. D1 leaves exactly one accent; a baked file is the approved pixels with no runtime
risk, for 21 kB. What keeps "the mechanism cheap to bring back":

- the manifest already models it (`lit: true`, `img/<slot>-lit-<w>.webp`);
- the asset script owns the ramp with the accent as a parameter (`assets.json` `"accent"`), so a pack
  is a second lit set (`…-lit-<pack>-96.webp`) and one lookup — not a design task;
- if user-picked accents ever return (`ui/theme/ThemeProvider.tsx:97-99` sets `--accent` at runtime
  today), the runtime lookup of row 4 is the path, and the CSP already allows it (`blob:`, `data:`).

Build neither of the last two now. Note the dependency: for another accent the ramp needs the
pre-levels masters — `tab-*.png` for five icons (in `kepek/`), `graded-tab-coach.png` /
`graded-tab-admin.png` for the other two (temp folder only, A0).

Rendering (agrees with `shell-gates.md` §5.1): both `<img>` of a tab stay in the DOM, stacked; the
lit one's opacity switches in `--duration-fast` (Pulse's "ignite"); pressed = 60 % opacity. The medal
uses the same pair (locked = idle at 45 % opacity, unlocked = lit). The coin has no lit state.

### 8.2 Pillow — the whole export, as run

wrote **49 files, 841,058 bytes** on this machine:

```python
"""Pulse asset export (Pillow). Usage: python -I build_pulse_assets.py <masters dir> <out dir>"""
import os, sys
from PIL import Image
import numpy as np

SRC, OUT = sys.argv[1], sys.argv[2]
CANVAS = np.array([11, 13, 10], np.float32)   # --surface-0, the Pulse canvas
KNEE = 32.0                                   # a pixel this far above the canvas is fully opaque

def knee_alpha(im):
    """True-black still -> RGBA whose composite over the canvas equals `lighten` exactly."""
    c = np.asarray(im.convert('RGB')).astype(np.float32)
    lit = np.maximum(c, CANVAS)
    a = np.clip((c - CANVAS).max(axis=2) / KNEE, 0, 1)
    safe = np.where(a > 0, a, 1)[..., None]
    rgb = np.where(a[..., None] > 0, CANVAS + (lit - CANVAS) / safe, CANVAS)
    return Image.fromarray(np.dstack([np.rint(rgb), np.rint(a * 255)]).astype(np.uint8), 'RGBA')

def fit(im, w):
    h = round(im.height * w / im.width)
```

### 8.3 sharp — the same two operations (verified against 8.2)

```js
const CANVAS = [11, 13, 10], KNEE = 32;

/** True-black still → RGBA whose composite over the canvas equals `lighten` exactly. */
async function kneeAlpha(file, width) {
  const { data, info } = await sharp(file).removeAlpha().resize({ width, kernel: 'lanczos3' })
    .raw().toBuffer({ resolveWithObject: true });
  const out = Buffer.alloc(info.width * info.height * 4);
  for (let i = 0, o = 0; i < data.length; i += 3, o += 4) {
    let m = 0;
    for (let c = 0; c < 3; c += 1) m = Math.max(m, data[i + c] - CANVAS[c]);
    const a = Math.min(1, Math.max(0, m / KNEE));
    for (let c = 0; c < 3; c += 1) {
      const lit = Math.max(data[i + c], CANVAS[c]);
      out[o + c] = a > 0 ? Math.min(255, Math.round(CANVAS[c] + (lit - CANVAS[c]) / a)) : CANVAS[c];
    }
    out[o + 3] = Math.round(a * 255);
  }
  return sharp(out, { raw: { width: info.width, height: info.height, channels: 4 } });
}

// black-background families (figure, hero, equipment)
await (await kneeAlpha(`${SRC}/hero-grip.png`, 432)).webp({ quality: 80, alphaQuality: 100, effort: 6 }).toFile(`${OUT}/hero-grip-432.webp`);
// transparent cut-outs (tab icons, coin, medal) — resize only
await sharp(`${SRC}/tab2-home.png`).resize({ width: 96, kernel: 'lanczos3' }).webp({ quality: 90, alphaQuality: 100, effort: 6 }).toFile(`${OUT}/tab-home-96.webp`);
// the texture
await sharp(`${SRC}/monogram-light.png`).resize({ width: 512 }).webp({ quality: 70, effort: 6 }).toFile(`${OUT}/texture-monogram-512.webp`);
```

### 8.4 A lit icon for another accent (not needed for the first release)

```python
def levels(a, gamma, lo, hi):                       # a: float array 0-255
    return np.rint(255 * ((np.clip(a, lo, hi) - lo) / (hi - lo)) ** gamma)

def lit_icon(master_rgba, accent):                  # master = the pre-levels cut-out, e.g. tab-home.png
    a = np.asarray(master_rgba).astype(np.float32)
    lv = np.dstack([levels(a[..., i], 0.70, 18, 225) for i in range(3)]).astype(np.uint8)
    t = (np.asarray(Image.fromarray(lv, 'RGB').convert('L')).astype(np.float32) / 255)[..., None]
    c = np.array(accent, np.float32)                # (203, 255, 46) is the Pulse lime
    low = c * (0.22 + 0.78 * np.clip(t / 0.6, 0, 1) ** 0.85)
    high = c + (255 - c) * 0.75 * np.clip((t - 0.6) / 0.4, 0, 1)
    return Image.fromarray(np.dstack([np.rint(np.where(t < 0.6, low, high)), a[..., 3]]).astype(np.uint8), 'RGBA')
```
