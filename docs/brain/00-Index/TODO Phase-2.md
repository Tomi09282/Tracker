## Security passes (mandatory before phase close)

- [x] **T2.10.1** Every new endpoint: zod `.strict()`, ownership re-validation, whitelisted sort/filter, rate tier assigned — `done` · enforced by `npm run check:routes` rather than by review: every `z.object()` in `src/` must be `.strict()`, with exactly one exemption (`lib/env.js`, where env vars come from the process and a strict schema would reject every unrelated OS variable). Proven load-bearing — removing one `.strict()` fails the gate by file and line. Ownership re-validation and whitelisted sort keys are covered by the abuse-path suite (T2.10.5)
- [x] **T2.10.2** Mass-assignment: explicit pick-lists on every update, never spread `req.body` — `done` · zero spreads of `req.body` anywhere in `src/`, and the gate now fails the build on `...req.body` or `Object.assign(..., req.body)`. Every update uses an explicit pick-list — spreading is the cheapest way to hand a client a column it was never meant to write
- [x] **T2.10.3** Log-write endpoints are idempotent-safe (a replayed set check must not double-count a PR or a future coin reward) — `done` · proven end to end: an exact replay returns 200 with `replayed: true` and mints nothing; the session volume does not double, because the rollups are RECOMPUTED as SUM() by trigger rather than incremented; a DIFFERENT payload against a recorded set is 409 with the stored values, not a silent overwrite
- [x] **T2.10.4** Abuse-path trace per endpoint (forge / replay / race / IDOR / extremes) — `done` · a route-table audit turned into a permanent gate, `npm run check:routes`. It walks every route in `src/` and asserts three things: authenticated unless on a written-down PUBLIC allowlist (with a REASON per entry, and a stale entry is itself a failure), a rate limiter on every write, and no id interpolated into SQL. **It found four unlimited writes on the first run**, the worst being `POST /calendar-feeds` — which mints a durable bearer credential to a training schedule, and which sat in the same file as a limiter that had been applied to the cheaper READ path instead. Also `/change-credentials`, which takes a password and was therefore an online guessing oracle for anyone holding a stolen session. Proven load-bearing: removing the mint limiter makes the gate fail by name
- [x] **T2.10.5** Security regression tests added for each critical route — `done` · the five abuse categories run against every route this phase added — FORGE (a client-sent rollup on finish is rejected, not dropped; an injection-shaped id never reaches SQLite), EXTREMES (duration past the schema bound, RPE 0, a zero id, a window below the floor, `Number.MAX_SAFE_INTEGER` as a link id — all 400/404, never a 500), REPLAY (a second finish is 404, never a second completion), RACE (two CONCURRENT starts yield one session, enforced by `workout_logs_one_live_unique` in the database rather than by the route checking first and writing second), and IDOR (every session transition against another user's log is 404). Smoke 313/313
